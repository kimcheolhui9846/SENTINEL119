# 데모 수보 하네스

배차 지도, 직접 입력, 모델 비교 화면은 누적 발화를 `POST /api/compare/decide`로 보낸다. 한 번의 모델 응답으로 기존 확률 그래프와 하네스 판정을 함께 만든다. 모델 비교 화면은 base와 SFT 점수를 각각 판정한다.

## 판단이 화면과 자원 배정에 반영되는 시점

- 수보요원의 발화는 대화 문맥에 들어간다. 새 판단은 신고자 발화에서 모델 식별자와 확률 분포를 검증한 뒤에만 확정한다.
- 출동 대분류가 확정되면 지도에서 가상 차량을 배정한다. 같은 가용 차량과 위치·도로 소요시간을 주면 같은 차량이 선택된다. 두 차량의 도로 소요시간이 같을 때는 차량 ID 순서를 사용한다.
- 병원 조회는 구급 대분류와 구급 세부유형이 모두 확정된 시점에 시작한다. 병원 선택에는 별도 모델 호출을 쓰며, 후보에 없는 병원이나 최댓값 동률은 추천을 만들지 않는다.
- 프로필에 등록된 명시적 취소나 이미 확정한 대분류와 충돌하는 새 확정 후보는 운영자 재검토 대상으로 표시한다. 지금까지의 모의 출동 이력은 유지한다. 임의의 한국어 정정문을 인식하는 범용 언어 판별기는 별도 검증이 필요하다.
- 차량 배정은 한 데모 세션의 가용 상태를 사용한다. 여러 관제 세션에서 같은 실차를 예약하는 운영 기능을 검증하려면 공유 자원 저장소가 필요하다.

## 다음 체크포인트 연결

1. 팀 모델 서버의 `/v1/stream`에서 합성 신고 한 건으로 SFT 체크포인트 메타데이터, base 리비전, 확률 필드와 라벨을 확인한다. 응답의 SFT 모델 메타데이터로 `backend/demo_harness.py`의 `_model_identity`가 계산한 전체 식별자를 사용한다.
2. [기본 프로필](../../backend/data/demo-harness.json)을 복사해 `version`과 `model_id`를 갱신한다. `SENTINEL_DEMO_HARNESS_PROFILE`에 새 JSON의 경로를 지정한다. `SENTINEL_ZORO_URL`은 모델 서버 주소다. 어휘나 점수 필드까지 바뀐 모델은 어댑터와 계약 테스트를 먼저 갱신한다.
3. 기본 H4 프로필의 출동 0.90, 화재 0.75, 세부유형·긴급도 0.85, 주증상 0.80은 팀의 기존 시연 기준에서 가져왔다. 새 모델의 기준을 조정할 때는 개발 통화를 사용하고, 분리한 평가 통화는 최종 비교에만 쓴다.
4. 프로필과 모델의 조합을 바꾼 뒤에는 새 신고로 시작한다. 기존 신고에서 모델 또는 정책 지문이 바뀌면 새 조치를 보류한다. 원본 예측, 정책이 허용한 판단, 이미 수행한 모의 출동을 각각 확인할 수 있다.

## H4 적용 전후 비교

합성 9통화 20턴의 누적 발화 중 같은 입력을 합친 18건을 팀 H4에 호출했다. 같은 응답을 기존 데모(`d14c6f6`)와 이 하네스에 재생했다. 아래 수치는 평가용 6통화 14턴의 **턴 종료 시점에 활성 상태인 출동 대분류**를 비교한 것이다. 개발·평가 통화 사이에 동일한 누적 입력 2개가 있다. 이 결과만으로 실제 신고의 정확도를 추정할 수 없다.

| 대분류 판정 | 기존 데모 | 하네스 적용 |
| --- | ---: | ---: |
| 올바른 확정 | 8 | 8 |
| 잘못 유지하거나 내린 확정 | 3 | 1 |
| 올바른 보류 | 3 | 5 |
| 근거가 있는데 보류 | 0 | 0 |

개선된 2턴은 같은 구급 신고의 명시적 철회와 그 다음 턴이다. 표현이 다른 화재 정정 1턴에서는 추천이 계속 활성 상태였다. 정정 문구와 임계값을 평가 결과에 맞춰 바꾸지 않았다. 병원·세부유형 정확도는 이 집계에 포함하지 않았다.

로컬에서 프로필 파일을 읽고 H4 응답을 검사하는 시간을 360회 측정했다. 중앙값은 0.50ms, 95백분위수는 1.81ms였다. 프로필을 미리 읽은 정책 함수만 1,440회 실행하면 각각 0.070ms, 0.150ms였다. 별도로 측정한 기존 base·SFT 동시 HTTP 요청 18건의 왕복 중앙값은 2.09초였다. 두 버전의 네트워크 왕복 속도 차이는 측정하지 않았다.

평가 통화와 턴별 기대값은 [기존 합성 검증 세트](https://github.com/kimcheolhui9846/SENTINEL119/blob/b16fb1d/data/demo/shadow-prefixes.jsonl)를 사용했다. 기본 프로필 지문은 `45c4d1e862204e22ccc4664c9a2699de3369e2aa00628ac9b8d48341a3b49225`, 로컬 원시 응답 JSONL의 SHA-256은 `72a35d801f3e65dcdd8a80cd30c6ead83aa4caa1f993227dd11fbfb290acb803`이다.
