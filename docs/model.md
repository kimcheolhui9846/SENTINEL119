# SENTINEL_ZORO 모델 구조와 학습

최종 모델 **H4**(`runs/zoro-hier-h4`)의 구조, 학습 순서, 손실 함수, 그리고 데모에서 턴 단위로 판단하는 방식을 정리한다. 실행 명령과 실험별 수치는 [학습 실행 안내](training.md) 10–11절에 있다. 아래 값은 `src/sentinel119/model.py`, `src/sentinel119/train.py`, H4의 `run.json`·`adapter/adapter_config.json`에서 확인했다.

## 1. 구조

- **바탕 모델:** [Zoro-1](https://huggingface.co/trillionlabs/Zoro-1)(Qwen3.5-4B 기반, revision `bf1b76b9`). 바탕 가중치는 고정한다.
- **LoRA:** 텍스트 디코더 attention의 `q_proj`·`k_proj`·`v_proj`·`o_proj`, rank 16, alpha 32, dropout 0. 비전 타워와 gated-delta(linear attention) 투영은 학습하지 않는다.
- **판단 head:** Zoro-1이 공개한 pointer head에서 시작해 LoRA와 함께 학습한다. 학습 파라미터는 약 446만 개다(LoRA 텐서 64개, head 텐서 4개).

입력은 질문마다 한 줄씩 만든다(`src/sentinel119/decision.py`).

```
<상태> 화자0/1: 신고 대화 … <질문> 질문 문구 <선택지> key: 설명 <끝> <선택지> … <끝> <판단>
```

판단 토큰의 hidden `h_decide`를 query로, 각 선택지 끝 토큰의 hidden `h_k`를 key로 써서 점수를 낸다.

```
logit_k = (W_k · h_k) · (W_q · h_decide) / √256        p = softmax(logit)
```

텍스트를 생성하지 않고 선택지 중 하나를 고르므로 L40S에서 판단 한 번이 약 130–250ms다. 확률은 온도 보정하지 않은 softmax(T = 1)다. 정답과 메타데이터는 입력에 넣지 않는다.

### 질문 계층

| 층 | 질문 | 선택지 | 열리는 조건 |
| --- | --- | --- | --- |
| 1 | 출동유형 | 화재·구조·구급·기타 | 항상 |
| 2 | 구급 세부유형 | 질병(중증)·질병(중증 외)·심정지·부상·사고·임산부·약물중독·기타구급 | 구급 |
| 2 | 구조 세부유형 | 안전사고·대물사고·자살·기타구조 | 구조 |
| 3 | 긴급도 | 상·중·하 | 항상 (데모에서는 출동유형 확정 후) |
| 3 | 구급 주증상 | 심정지·호흡정지, 흉통, 마비, 기록된 증상 없음 등 15개 그룹 | 구급 |

화재·기타 세부유형은 긴급도·출동 판단에 정보가 거의 없어 1층에서 끝낸다. 주증상 정답은 AI Hub `symptom` 목록에서 위중도 우선순위가 가장 높은 그룹 하나로 만든다.

## 2. 학습 순서

학습 데이터는 AI Hub 119 신고 데이터 공식 Training에서 (출동유형, 세부유형, 긴급도)로 층화한 8,000통화다. 희소 세부유형은 최소 건수를 확보했다. 정답은 통화 전체에 붙은 라벨(`label_scope: full_call`)이고 학습에는 통화 전체를 넣는다.

| 단계 | 시작점 | 학습 데이터 | 주요 설정 | 선택 |
| --- | --- | --- | --- | --- |
| H1b | 원본 Zoro-1 | 8,000통화 | LoRA attention r16 α32, 학습률 1e-4, cosine, warmup 5%, 1,200 step | 900 step |
| H3 | H1b | H1b가 보지 않은 통화 | 이어 학습, 550 step | — |
| **H4** | H3 | H3까지 보지 않은 2,200통화 | 학습률 2e-5, cosine, warmup 5%, 550 step, seed 319 | **440 step** |

- 이어 학습할 통화는 `tools/continuation_split.py --run <이전 체크포인트>`로 만든다. 이전 실행이 학습 순서대로 소비한 통화를 빼고 나머지를 새 train으로 쓴다. 이렇게 하면 이전 실행이 본 통화를 다시 보지 않고, 평가 통화는 그대로 둔다.
- 시작점은 `--init-checkpoint`로 지정한다. 이전 head와 LoRA 어댑터를 불러와 둘 다 계속 학습한다. 그래서 H4의 어댑터 형태(r16, q·k·v·o)는 H1b에서 정한 값을 따른다.
- 배치는 한 번에 1통화, gradient accumulation 4다.
- 110 step마다 dev 300통화에서 **출동유형·긴급도 NLL**을 재고 가장 낮은 step을 고른다. 세부유형·주증상은 선택 기준에 넣지 않고 출동유형까지 맞힌 경우의 정확도로 따로 기록한다.

## 3. 손실 함수

`training_loss`는 질문별 cross-entropy의 가중 평균이다.

```
L = Σ_i w(q_i) · CE_i / Σ_i w(q_i)        CE_i = −log p_i[정답]
```

| 질문 | 가중치 `w` | 옵션 |
| --- | ---: | --- |
| 출동유형 | 1.0 | 기본값 |
| 긴급도 | 1.5 | `--urgency-weight 1.5` |
| 구급 세부유형 | 1.0 | `--task-weight ems_subtype=1.0` |
| 구조 세부유형 | 1.0 | `--task-weight rescue_subtype=1.0` |
| 구급 주증상 | 0.3 | `--task-weight ems_symptom=0.3` |

- 긴급도는 하향 오판 비용이 커서 가중치를 높였다. 주증상은 라벨이 여러 증상 중 하나를 고른 것이어서 가볍게 둔다.
- 학습 중에는 선택지 순서를 매번 섞어 위치를 외우지 않게 한다.
- 코드에는 긴급도 label smoothing(`--urgency-label-smoothing`), 하향 오판에 더 큰 비용을 주는 기대 비용 항(`--urgency-cost-weight`, `--downward-cost`), 출동유형 logit adjustment(`--dispatch-logit-adjust`)도 있다. H4에서는 모두 0으로 꺼 두어 순수한 가중 cross-entropy다.
- 평가와 체크포인트 선택에는 가중치 없는 평균 NLL(`supervised_loss`)을 쓴다.

## 4. 턴 단위 판단

모델은 통화 전체로 학습하지만, 데모는 매 턴 **그때까지 들어온 대화만** 넣어 판단한다. 판단 서버의 `POST /v1/stream`이 같은 대화 앞부분에 대해 SENTINEL_ZORO(H4)와 base(어댑터를 끈 원본 head)의 질문별 확률을 함께 돌려준다.

데모는 태스크마다 다음 규칙으로 WAIT/COMMIT을 정한다(`frontend/src/CompareView.tsx`의 `advance`).

1. 출동유형의 1순위 확률이 그 유형의 임계값 이상이면 확정한다.
2. 출동유형이 확정된 뒤에만 세부유형·긴급도·주증상을 판단한다. 각 태스크의 1순위 확률이 임계값 이상이 되는 첫 턴에 확정한다.
3. 한 번 확정한 값은 바꾸지 않는다. 이후 다른 선택지가 임계값을 넘으면 화면에 재검토 표시만 한다.
4. 판단 서버가 응답하지 않은 턴은 이전 확정 상태를 유지하고, 다음 턴에 전체 대화로 다시 판단한다.

확정 결과는 다음 동작으로 이어진다.

- 출동유형이 확정되면 지식베이스 편성 규칙으로 차량을 배차한다. 심정지가 확정되면 펌뷸런스를 추가하는 식으로, 이후 확정이 편성을 바꿀 수 있다.
- 구급이면 주증상(확정 전에는 1순위 추정)으로 이송 원칙을 정한다. 국립중앙의료원 병원 정보로 후보를 만들고 Zoro가 이송 병원을 고른다.

### 임계값

임계값은 dev 통화의 모든 턴 앞부분을 H4와 base로 채점해 정했다. 맞는 확정 +1, 틀린 확정 −2, 확정하지 않음 0의 합이 최대가 되는 값을 0.40–0.99(0.01 간격)에서 찾는다. 출동유형 유형별 값을 먼저 정한 뒤 하위 태스크를 정한다. 같은 임계값을 두 모델에 적용한다.

| 태스크 | 임계값 |
| --- | --- |
| 출동유형 | 구급 0.66 · 구조 0.86 · 화재 0.79 · 기타 0.82 |
| 구급 세부유형 | 0.86 |
| 구조 세부유형 | 0.68 |
| 긴급도 | 0.82 |
| 구급 주증상 | 0.69 |

벌점을 −4로 두면 확정 정밀도는 100%였지만 세부유형·긴급도·주증상을 3–17% 통화에서만 확정해, 데모에는 −2를 쓴다. 이 임계값에서의 정밀도와 확정률, 최종 test 결과는 [루트 README](../README.md#평가-결과)에 있다. 체크포인트를 바꾸면 임계값을 다시 정한다.
